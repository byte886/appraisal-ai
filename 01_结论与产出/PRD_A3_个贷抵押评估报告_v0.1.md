## 1. 业务背景：这是什么业务（写给非行业读者）

### 1.1 个贷抵押估价是什么
个人（或小微企业）以房地产作抵押向银行申请贷款时，银行需要知道抵押物"值多少钱"，据此定贷款额度（额度≈评估值×抵押率）。为此由**具备资质的房地产估价机构**出具一份《房地产抵押估价报告》，对抵押物在某一**价值时点**的**抵押价值**进行分析、估算并判定。这就是"个贷抵押评估"。

- 委托方：多数为贷款银行（机构常以"入围"方式进入银行服务商名单），也可能是借款人/中介；【待核：海口公司主要委托来源与银行是否指定模板】。
- 产出物：名称必须为**《房地产抵押估价报告》**，估价机构出具、**盖公章、至少 2 名专职注册房地产估价师签字**【规范·抵押意见第27条】。
- 为什么是尖刀：住宅个贷**高度标准化、笔数多、银行催得急**（合伙人原话"量最多、要求要快"）；方法以比较法为主、数据需求相对收敛，最适合先做深。

### 1.2 抵押价值怎么算（与普通市场价的区别）
**房地产抵押价值 = 假定未设立法定优先受偿权利下的市场价值 − 估价师知悉的法定优先受偿款**【规范·抵押意见第4条】。
- 法定优先受偿款：如发包人拖欠承包人的建筑工程价款、已抵押担保的债权数额、其他法定优先受偿款。
- 抵押估价还要做**变现能力分析**（通用性、独立使用性、可分割转让性、变现税费与时间），并**提示未来价格下跌风险、抵押期信贷关注点、合理使用价值、价格快变时再评估**【规范·抵押意见第22/23条】。
- 若委托要求评估"抵押净值"，再扣预期损失/税费等；土地增值税等复杂扣减建议委托专业机构，否则在假设中说明。

### 1.3 估价方法（首战只做深比较法）
- **比较法（市场比较法）**：找 ≥3 个近期成交的相似房子（可比实例），标准化后做交易情况、市场状况（时间）、房地产状况（区位/实物/权益）修正，综合得出比准价格。住宅首选。详见 M3 spec。
- **收益法**：靠租金收益折现，适合商铺/写字楼/公寓等；个贷住宅通常为辅。**列二期**。
- 成本法、假设开发法等：首战不做。

### 1.4 报告怎么生产、怎么审核（现状流程）
典型作业链：**接单/立项 → 实地查勘 → 市场调研找案例 → 选方法测算 → 撰写报告 → 内部审核 → 盖章出具 → 归档**。
- 机构内部通常有编制人 + 多级审核（一审/二审/三审）质控；竞品宣称用 AI 替代一审、二审、仅保留人工三审，单份审核 5–6 分钟→约 1 分钟【竞·一方称】。
- 痛点（来自需求池与同事方案）：找可比案例耗时、系数/文字重复劳动、Word 排版与数据勾稽易错、跨章节数字不一致、审核退回返工。

### 1.5 竞品在个贷线上的已知做法（对标，不照抄）
- 处理链：自动信息提取 → 可比案例筛选 → 百度地图生成标的位置截图 → 报告排版，宣称约 1 分钟出完整合规报告【竞·一方称，竞品库 04 A3-3】。
- 一份报告拆成市场背景、区位分析、比较法计算、收益法计算、成本法计算、案例筛选、地图截图、排版等**独立 Skill**，单独调试、跨报告类型拼装复用【竞】。
- 审核按物业类型分 Skill（house-review / bank-shop-review / office-review / factory-review）【竞】。

## 2. 目标与非目标

### 2.1 本期目标（两人自用，ADR-002）
- 让开发+估价师合伙人在**真实个贷住宅抵押报告**上，把"找案例→测算→撰写→勾稽→排版"的重复工时显著降下来（G2 目标：单份工时降 ≥50%，争取 80%），且产出报告能通过机构终审、可盖章出具。
- 沉淀可复用的：数据契约、比较法引擎、报告模板、勾稽/合规规则。

### 2.2 非目标（本期明确不做）
- 不做自动签发/自动定稿（**签字责任永远在估价师**）；不做可研、征收、招投标、车辆/资产评估线；不做收益法/成本法引擎（仅占位）；不做自动取系数、自动爬取定价；不做多租户、私有化安装包、机构权限、计费；不做移动端、多人协作。
- 不以"签约付费客户"为近期目标（老板当前不付费，仅潜在客户）。

## 3. 用户、角色与端到端旅程

| 角色 | 本期是谁 | 职责 |
|---|---|---|
| 编制人/估价师 | 合伙人（吴总） | 查勘、选实例、定系数、改稿、对结论负责、签字 |
| 开发/运营 | 用户（开发） | 配置模板/规则、跑工具、维护数据与系统、兼操作 |
| 审核人 | 合伙人/机构终审 | 终审把关（自用阶段一人多角，系统做 G1/G2 预检） |

**端到端用户故事（自用最小闭环）**：
1. 新建项目，录入委托与标的（或从权证/查勘表带入）；
2. 录入/采集可比实例，系统校验数量、时点、来源；
3. 录入修正系数（本期），系统完成五统一换算、连乘计算、红线校验、出系数表；
4. 系统按模板生成各章节草稿与测算过程，区位/市场段半自动；
5. 系统跑勾稽与合规预检（G1/G2），列出问题；
6. 估价师改稿确认→导出符合公司模板的 Word→人工终审、签字、盖章、归档。

## 4. 报告结构与"人机分工"映射（M1 模板蓝图）

> 【规范】抵押估价报告由：封面/目录、致估价委托人函、注册房地产估价师声明、估价假设和限制条件、**估价结果报告**、**估价技术报告**、附件构成；结果报告 13 项、技术报告 7 部分缺项即不合格（来源见第 12 节）。

| 报告部分 | 主要内容 | 本期生成方式 |
|---|---|---|
| 封面/目录/致委托人函 | 项目名、委托人、机构、价值时点、结果摘要 | 模板+字段填充，目录自动 |
| 估价师声明 | 固定声明 + 签字估价师 | 固定模板（≥2 人），手签/盖章线下 |
| 假设和限制条件 | 通用假设 + 特殊事项（未鉴定/未测量/优先受偿款等） | 模板库+按标的勾选补充 |
| **估价结果报告（13 项）** | 委托人/机构/目的/对象/时点/价值类型/依据/原则/方法/结果/估价人员/作业日期/报告有效期等 | 字段填充为主，AI 组织表述 |
| **技术报告①个别因素②区域因素** | 实物、权益、区位状况描述 | 查勘字段+采集素材，AI 起草、人工改 |
| 技术报告③市场背景分析 | 同类房地产过去/现在/未来市场 | 采集+AI 综述（P1，需来源） |
| 技术报告④最高最佳使用分析 | 法定/可能/可行/价值最大化 | 住宅多为模板化表述，人工确认 |
| 技术报告⑤估价方法选用 | 用比较法的理由、不用其他法的理由 | 规则生成初稿 |
| 技术报告⑥估价测算过程 | 可比实例表、五统一、修正系数表、计算 | **M3 引擎自动成表成段**（核心） |
| 技术报告⑦估价结果确定 | 综合取值与理由、最终单价/总价/抵押价值 | 引擎计算+人工确认理由 |
| 风险提示/变现能力分析 | 抵押特有 | 模板+标的要素生成，人工把关 |
| 附件 | 委托书、权证、位置图、查勘内外部照片、可比实例位置图外观照、机构资质/营业执照/估价师证 | 占位+上传清单校验（缺件提示） |

> 【待核】公司真实 Word 模板（P0 材料 F1）与 2–3 份脱敏完整报告（F2）到位后，本节按真实章节顺序、字号、表格样式、固定表述逐字校准。

## 5. 功能需求（按端到端流程）

> 优先级：P0=自用最小闭环必做；P1=提效明显、可稍后；P2=增强。每项给输入/系统行为/可见结果/异常/验收要点。

### F1 项目创建与委托、标的录入（P0）
- 触发：接到一笔个贷抵押委托。输入：委托/银行、标的基本信息、价值时点。
- 系统行为：建项目；引导按 `SubjectProfile` 七组录入必填项；缺失必填给清单；自动带入机构/估价师/目的等 config。
- 可见结果：一份结构化标的画像，后续全程复用。
- 异常：必填缺失不得进入测算；权属/他项权利异常（查封、已抵押）显著标红提示。
- 验收：同一信息只录一次，报告各章节自动一致。

### F2 查勘信息与证件录入（P0 手工，OCR 列 P1）
- 输入：查勘表、不动产权证、内外部照片、查勘记录。
- 系统行为：v0.1 手工录入+照片上传与命名归类；P1 做产证 OCR 字段提取（竞品有移动端产证识别【竞】）。
- 可见结果：实物/权益/照片齐备并映射到报告与附件。
- 异常：未能进入内部查勘须按规范记录原因；照片缺件在附件清单提示。
- 验收：查勘字段能直接生成技术报告①个别因素草稿。

### F3 可比实例采集与管理（P0，M2）
- 输入：成交/挂牌/询价来源（中介、平台、同行、公司案例库）。
- 系统行为：录入 `ComparableInstance`，**强制来源凭证（URL/截图/查询时间）**；按物业类型/片区/面积段给相似度排序建议；记录挂牌→成交折让处理【待核口径】。
- 可见结果：候选实例列表 + 是否满足 ≥3、时点、相似性的提示。
- 异常：不足 3 个阻断比较法；来源缺失不得入算。
- 验收：每个实例可回源；实例字段够支撑修正系数表。

### F4 比较法测算引擎（P0，M3，核心）
- 完整规则见 [`specs/M3计算引擎_比较法_规范版_v0.1.md`](specs/M3计算引擎_比较法_规范版_v0.1.md)。
- 系统行为：五统一换算→K1/K2/K区位/K实物/K权益 连乘→红线校验（实例≥3、时点≤1年/2年、单项≤20%、综合≤30%、最高最低比≤1.2）→综合比准→乘面积得市场总价→减法定优先受偿款得抵押价值。
- 可见结果：修正系数表、可比实例表、测算过程文字段、`qc_flags`。
- 验收：与估价师 Excel 手算**逐格一致**；越界必提示；改输入全联动。

### F5 区位地图与市场背景（P1）
- 地图：标的位置/周边配套截图（竞品用百度地图【竞】；具体地图 API 与配额待选，注意授权）。
- 市场背景：片区成交/均价/走势采集 + AI 综述，强制带来源；无可靠来源时只给占位、不编数字。

### F6 报告章节生成与拼装（P0，M4+M1）
- 系统行为：按第 4 节蓝图，以"章节 Skill/模板"方式生成各段（固定段模板、描述段 AI 起草、测算段取 F4 结果）；一处数字来自同一数据契约，禁止手填出第二份。
- 可见结果：完整报告草稿（先在编辑器内可改）。
- 异常：某段缺数据→留带说明的占位并列入缺口清单，不生成看似完整实则缺项的报告。
- 验收：章节顺序/固定表述符合公司模板（待 F1 校准）；AI 文字可溯源、可一键改。

### F7 合规与勾稽校验（P0，对应竞品 A2，G1/G2）
- G1 市场区间：F4 红线 + 比准价与片区行情/实例区间合理性。
- G2 合规与勾稽：结果报告 13 项/技术报告 7 部分/附件缺项检查；跨章节数字、大小写金额、单价面积总价、抵押价值公式一致性；抵押风险提示与二人签字占位；时效（报告有效期）。
- 输出：问题清单（阻断/警告/建议），定位到章节；**通过不代表可出具，终审仍在人**。

### F8 人工终审、签字与导出 Word（P0，M6）
- 导出符合公司模板的 .docx（表格、字号、页眉页脚、目录、附件占位）；估价师线下/电子签字盖章；导出件留版本。
- 异常：存在阻断项时禁止导出"终稿"（可导出带水印"过程稿"）。
- 验收：导出 Word 与编辑器预览一致，可直接进终审流程。

### F9 归档与知识沉淀（P2，M5）
- 项目、实例、系数、模板、踩坑沉淀为本地知识库/案例库，反哺后续选实例与表述；自用阶段从简（本地目录/文件即可）。

## 6. 数据与溯源
- 全系统以数据契约为唯一输入输出口径；外部数据（成交、指数、配套）必带来源四要素（来源、链接/凭证、抓取时间、信源等级）。
- 只用**脱敏样本**入系统/样本库；敏感件（含产权人全名、身份证、电话、账号、精确房号）不进结构化库或脱敏后存储。
- 第三方成交/指数数据是否付费、预算与授权待定（ISSUES-006/012，等 Q6）。

## 7. 合规、安全与责任边界（红线）
1. AI 是辅助，**报告结论与签字法律责任在注册房地产估价师和机构**；系统不签发、不定稿、不对外承诺价值。
2. 数据可溯源、可回查；AI 生成内容须可定位依据，禁止编造案例、数字、政策。
3. 抵押特有要素（法定优先受偿款、变现能力、风险提示、再评估提示）必须到位。
4. 自用阶段也在处理合伙人公司职务数据：仅内部研究与自用，脱敏、最小必要；商业化前需谈清数据授权与 IP 归属（ISSUES-013）。
5. 竞品付费资料仅用于内部逆向研究，不公开传播原件。

## 8. 勾稽与校验规则清单（F7 的规则源，随 F3/F4 细化）
- [ ] 可比实例 ≥3；成交日距时点 ≤1 年提示 / >2 年阻断
- [ ] 单项修正 ≤20% 提示理由；综合 ≤30%；最高/最低比较价 ≤1.2
- [ ] 单价×面积=总价；大小写金额一致；币种一致
- [ ] 抵押价值=市场价值−法定优先受偿款（扣减有明细/假设）
- [ ] 结果报告 13 项、技术报告 7 部分、附件必备项无缺
- [ ] 跨章节同一数字一致；签字 ≥2 人；报告有效期已填
- [ ] 外部数字均有来源；照片/权证/委托书附件齐全
（阈值适用性与公司内部口径待估价师确认）

## 9. 提效度量（自用 G2，先定义口径不承诺幅度）
- 埋点/手记各环节耗时：接单录入、找实例、测算、撰写、排版、审核退回次数、总工时。
- 口径：同一类报告"纯人工基线 vs 用工具后"对比，样本 ≥3–5 份真实报告；记录是否一次过终审、退回原因。
- G2 判定：工时下降达标 + 报告过审 + 合伙人愿意持续用，再谈商业化。

## 10. 分期里程碑（自用）
- **M0（当前，不依赖真实材料）**：数据契约、比较法规范引擎、本 PRD 骨架、报告模板蓝图。
- **M1（待 F3 测算 Excel）**：手工录入→比较法测算→系数表/测算段，1 份真实住宅报告的测算环节跑通且与手算一致。
- **M2（待 F1 模板/F2 报告/F4 查勘表）**：全章节拼装 + 勾稽校验 + 导出公司模板 Word，跑通完整 1 份。
- **M3**：3–5 份真实个贷报告对照验证工时与过审（G2），再决定是否补收益法/地图/OCR。
