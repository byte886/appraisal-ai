# M3 计算引擎 · 比较法（市场比较法）规范版 spec · v0.1

> 归属：A3 个贷抵押评估报告 PRD 的核心模块 M3；可被住宅/商铺/写字楼等多报告类型复用（版块×方法分离）。
> 状态：**v0.1 规范骨架**。流程与红线来自现行国标与抵押估价指导意见（【规范】）；**具体系数取值、综合方式、权重以估价师比较法测算 Excel（P0 材料 F3）为准**，到位前不内置任何"经验数值"。
> 一句话：系统不替估价师"拍价"，而是把规范七步固化成可复算、可溯源、越界即提示的计算流水线，系数本期以人工录入为主。

---

## 1. 适用对象与前置

- 适用：存在活跃交易市场、能取得 ≥3 个可比实例的住宅/商铺等个贷抵押标的（首战=个人住宅抵押）。
- 不适用/需切方法：无足够可比实例（特殊物业、偏远区域）→ 提示改用收益法/成本法（后置），不强行出比较法结论。
- 前置输入：`SubjectProfile`（数据契约 §1）已完成必填项；`ComparableInstance[]` ≥3 条且带来源凭证；价值时点已确定。

## 2. 规范七步 → 系统行为映射

> 【规范·GB/T 50291-2015 §4.2.1】比较法七步：①搜集交易实例 ②选取可比实例 ③建立比较基础 ④交易情况修正 ⑤市场状况调整 ⑥房地产状况调整 ⑦计算比较价值。（注意：1999 旧版为八步、措辞为交易日期/区域因素/个别因素修正，本产品以 2015 现行版为准。）

| 步骤 | 规范要求 | 系统行为（v0.1） | 人工/自动 |
|---|---|---|---|
| ①搜集交易实例 | 搜集大量真实成交，掌握行情 | M2 采集成交/挂牌/询价，按片区入库，强制来源留痕 | 采集半自动，估价师确认 |
| ②选取可比实例 | 与标的相似、交易方式适合目的、**≥3 个**、成交日接近时点 | 按物业类型/片区/面积段/用途筛选候选并给相似度排序；不足 3 个阻断并提示 | 系统推荐，**估价师勾选确认** |
| ③建立比较基础 | 标准化：统一财产范围、付款方式、融资条件、税费负担、计价单位（§4.2.6） | 对每个实例做"五统一"换算（如附赠车位剔除、税费各付归一、统一为元/㎡建筑面积） | 规则自动+人工确认换算项 |
| ④交易情况修正 | 把非正常交易价格修正为正常价格 | 应用交易情况修正系数 K₁（急售/关联交易/议价偏离） | 系数人工录入，系统算 |
| ⑤市场状况调整 | 成交日→价值时点的市场价格变化 | 应用市场状况调整系数 K₂（价格指数/变动率，按片区或同类） | 指数来源留痕；系数可手工 |
| ⑥房地产状况调整 | 区位/实物/权益三方面差异调整 | 应用 K₃=K区位×K实物×K权益（楼层、朝向、装修、成新、年代、临街、土地剩余年限等） | **系数本期人工录入**，逐项给依据 |
| ⑦计算比较价值 | 求各实例比较价值并综合 | 逐实例算比较单价→合规校验→综合为比准单价→乘面积得总价 | 自动；综合方式与权重待核 |

## 3. 计算模型（公式）

**3.1 单实例比较单价**（建立比较基础后的单价 P₀ 上连乘各系数）：

```
P_i = P0_i × K1_i(交易情况) × K2_i(市场状况) × K3_i(房地产状况)
K3_i = K区位_i × K实物_i × K权益_i
P0_i = 标准化后成交单价（五统一完成，元/㎡建筑面积）
```

**3.2 比准单价（多实例综合）**：

```
P_比准 = Σ(P_i × w_i) / Σw_i        # 加权；w_i 等权时=简单算术平均
```

**3.3 比较法评估总价**：

```
V_市场 = P_比准 × 建筑面积            # 口径必须与单价一致（建筑面积/㎡）
```

**3.4 抵押价值（数据契约 §3）**：

```
V_抵押 = V_市场(假定无法定优先受偿权) − 法定优先受偿款
```

> 【待核·关键】系数的**基准方向**（以估价对象=100 还是以可比实例=100）、百分率法还是差额法、综合用等权还是加权及权重规则，各公司 Excel 口径不同，**必须以估价师 F3 测算表为准统一实现**，避免方向取反。系统将在系数录入处明确标注"实例→标的"方向并做符号自检。

## 4. 规范红线自动校验（G1 市场区间门，硬提示）

> 下列阈值【规范·GB/T 50291-2015 §4.2，多地方政府/估价师学会文件一致引用】；系统在出结果前自动检查，**越界给警告、不静默放行**。

| 编号 | 规则 | 系统动作 |
|---|---|---|
| R1 | 可比实例 **≥3 个** | 不足则阻断比较法，提示补实例或换方法 |
| R2 | 成交日距价值时点 **不宜>1 年、不得>2 年** | >1 年黄色提示，>2 年红色阻断（特殊情况须人工说明） |
| R3 | 单项修正/调整幅度 **不宜>20%** | 超 20% 黄色警告，要求填理由 |
| R4 | 综合（共同）修正调整幅度 **不宜>30%** | 超 30% 红色提示，建议更换实例 |
| R5 | 调整后各实例比较单价 **最高价/最低价 比值 ≤1.2** | >1.2 提示离散过大、更换实例或说明 |
| R6 | 成交价格应为正常价格或可修正为正常价格 | 非正常且无法修正的实例不得入选 |
| R7 | 超阈值但因标的/市场特殊无更合适实例 | 允许例外，但**强制在报告中写明理由**（规范允许的披露路径） |

> 【待核】20%/30%/1.2 阈值在国标条文与房屋征收评估技术文件中表述一致；**抵押估价实务是否完全照搬、公司内部是否有更严口径，需估价师确认**后再设为硬/软门。

## 5. 勾稽与自检（G2 合规门的计算部分）

- 单价×面积=总价，跨章节同一数字一致（结果报告、技术报告、致委托人函、抵押价值汇总表）。
- 大小写金额一致；币种一致。
- 比较单价与各实例原始单价偏差落在合理带（配合 R3/R4/R5）。
- 抵押价值=市场价值−法定优先受偿款，扣减项有明细或在假设中说明。
- 每个系数/指数可点回来源（实例凭证、指数来源、估价师录入），满足评审回查。
- 收益法并用时（商业），两法结果差异、最终取值与权重须有书面理由（二期）。

## 6. 输出物（喂给 M4 撰写/M6 导出）

1. **比较法修正系数表**（实例×系数矩阵：成交单价、五统一调整、K1/K2/K区位/K实物/K权益、比较单价），插入技术报告"估价测算过程"。
2. **可比实例表**（名称/位置/成交日/用途/结构/面积/单价/来源），附位置图与外观照片占位。
3. **测算过程文字段**（方法选用理由、每步取值与依据、综合方式、结果），AI 起草、估价师改。
4. `qc_flags`：R1–R7 与勾稽检查结果（通过/警告/阻断+理由）。
5. 结构化 `ValuationResult`（数据契约 §3）。

## 7. 分期与边界

- **v0.1（自用 MVP）**：实例与系数人工录入/半自动采集；系统负责五统一换算框架、连乘计算、红线校验、勾稽、成表成段。**不做**自动取系数、不做自动爬取定价。
- **二期**：接入片区价格指数/成交库辅助 K2 与因素系数（待数据源授权与预算，ISSUES-006/012）；收益法/成本法引擎；AI 推荐系数但必须人工确认。
- **责任红线**：系统只给测算与提示，**最终取值、方法选用、报告结论与签字由注册房地产估价师负责**；AI 不签发、不自动定稿。

## 8. 验收（成功/失败场景）

- 成功：录入标的+≥3 实例与系数，系统产出的系数表/比准单价/总价与估价师 Excel 手算结果**逐格一致**；故意制造超 20%/30%、实例<3、日期>2 年、最高/最低>1.2 时分别给出对应警告/阻断；改任一输入，所有引用处联动更新。
- 失败兜底：实例不足/数据缺失→明确阻断并告知缺什么，不输出带缺口的"完整报告"；系数方向存疑→提示人工核对，不替用户猜。

## 9. 依据与待核

- GB/T 50291-2015《房地产估价规范》§4.2 比较法（住建部官方 PDF；顺德/庆城县政府镜像 PDF 同文）。
- 修正幅度 20%/30%、最高最低比 1.2：重庆市住建委《国有土地上房屋征收评估技术规范》、沾化区政府镜像规范 PDF 引国标条文（抵押场景适用性待估价师确认）。
- 可比实例数量/时点：衢州市住建局征收评估技术指导意见（引国标口径）。
- 抵押价值公式与二人签字：《房地产抵押估价指导意见》（建住房〔2006〕8 号）第 4、27 条，中国房地产估价师与房地产经纪人学会 cirea.org.cn/content/4759。
- 待核：系数基准方向、综合方式与权重、本地因素系数经验区间、价格指数来源、公司 Excel 口径（P0 材料 F3）。
