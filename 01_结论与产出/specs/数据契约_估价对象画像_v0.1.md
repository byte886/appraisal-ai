# 数据契约 · 估价对象画像 / 可比实例 / 输出（v0.1 规范版骨架）

> 归属：A3 个贷抵押评估报告 PRD 的底层数据规范，供 M2 采集、M3 测算、M4 撰写、M6 导出共用（各模块的"通用插头"，对应同事方案的"估价对象画像 JSON"七组字段）。
> 状态：**v0.1 骨架，待估价师 P0 材料（查勘表/受理单 F4、测算 Excel F3、真实报告 F2）补全与核验**。
> 证据约定：【规范】=GB/T 50291-2015、《房地产抵押估价指导意见》等（来源见 A3 PRD 第 12 节）；【竞】=竞品做法（一方称）；【待核】=待估价师确认；字段命名给中英双语 key，便于后续直接落 JSON/表结构。

---

## 0. 设计原则

1. **一次录入、全程复用**：估价对象信息只录一次，测算、撰写、导出、审核共用，杜绝同一数字在不同章节手填不一致。
2. **三类字段分清来源**：`manual`（人工录入/查勘）、`source`（外部采集，必带来源凭证）、`calc`（系统计算，必带计算依据）。
3. **每个外部数据可溯源**：`source` 类字段强制带 `sourceUrl / sourceName / capturedAt / screenshot`，满足评审回查。
4. **敏感信息最小必要 + 脱敏**：产权人姓名、身份证、电话、账号、精确房号不入结构化库或先脱敏（见 A3 PRD 第 7 节）。
5. **数值带单位与口径**：面积 ㎡、单价 元/㎡、总价 万元/元（统一）、日期 YYYY-MM-DD；金额单位全项目统一并在导出时大小写自动生成。

## 1. 估价对象画像 `SubjectProfile`

> 七组主结构沿用同事方案（定位/用途/面积/实物/权益/时点/交易），按抵押估价与规范结果报告项补全。【待核：字段增删以估价师查勘表/受理单为准】

### 1.1 定位 `location`
| key | 含义 | 类型 | 必填 | 来源 | 说明/校验 |
|---|---|---|---|---|---|
| province/city/district | 省/市/区 | string | 是 | manual | 海口/海南先行 |
| address | 坐落（小区+楼栋，精确房号脱敏存储） | string | 是 | manual | 报告"估价对象"坐落；精确房号可仅在导出件出现 |
| community | 小区/楼盘名 | string | 是 | manual | 可比实例匹配主键之一 |
| lng/lat | 经纬度 | number | 否 | source/manual | 地图截图、距离测算用【竞：百度地图截图】 |
| peripheral | 周边配套（交通/学校/商业/医院） | text | 是 | source+manual | 区位状况描述素材，采集留痕 |
| plot_photo | 位置图/外观/内部照片 | file[] | 是 | manual(查勘) | 附件必备【规范：实地查勘照片】 |

| land_purpose | 土地用途 | enum | 是 | manual | 城镇住宅/商服… |
| is_residential_loan | 是否个贷住宅抵押 | bool | 是 | manual | 本产品首战=true |

### 1.3 面积 `area`

|---|---|---|---|---|---|

## 2. 可比实例 `ComparableInstance`（比较法，列表，≥3 条）

> 【规范】可比实例**不得少于 3 个**；成交日距价值时点**不宜超过 1 年、不得超过 2 年**；用途/结构/档次相近、区位相近。

| key | 含义 | 类型 | 必填 | 来源 | 校验/说明 |
|---|---|---|---|---|---|
| cid | 实例编号 | string | 是 | system | C1/C2/C3… |
| source_type | 来源类型 | enum | 是 | source | 真实成交/中介挂牌/询价/平台库；挂牌需折让处理【待核口径】 |
| sourceUrl/sourceName/capturedAt/screenshot | 来源凭证 | - | 是 | source | **强制留痕**，附件中放位置图+外观照片 |
| address/community | 坐落/小区 | string | 是 | source | 与标的同片区 |
| deal_date | 成交日期 | date | 是 | source | 与 value_date 比较，超期触发提示 |
| deal_total_price | 成交总价（万元） | number | 是 | source | |
| deal_unit_price | 成交单价（元/㎡） | number | 是 | calc | =总价/面积，系统复算 |
| building_area | 建筑面积 ㎡ | number | 是 | source | 统一计价基础 |
| payment/financing/tax_bearing | 付款方式/融资条件/税费负担 | enum | 是 | source/manual | 建立比较基础的"五统一"用 |
| property_scope | 财产范围（含车位/家具/附赠？） | text | 是 | source | 统一财产范围 |
| price_unit_basis | 计价单位口径 | enum | 是 | source | 统一为 元/㎡建筑面积 |
| loc_factors | 区位因素特征 | object | 是 | source/manual | 交通/配套/环境/楼层差（商铺临街） |
| phy_factors | 实物因素特征 | object | 是 | source/manual | 建成年代/装修/朝向/成新/面积 |
| right_factors | 权益因素特征 | object | 是 | source/manual | 土地剩余年限、权利负担 |
| deal_circumstance | 交易情况（正常/急售/关联交易） | enum | 是 | manual | 非正常需交易情况修正 |
| k_deal/k_time/k_loc/k_phy/k_right | 各修正/调整系数 | number | 是 | calc/manual | **本期手工录入为主，规范红线见 M3 spec** |
| adjusted_unit_price | 修正后比较单价 | number | 是 | calc | 见 M3 公式 |

## 3. 计算结果与报告输出 `ValuationResult`

| key | 含义 | 类型 | 来源 | 勾稽/校验 |
|---|---|---|---|---|
| comp_unit_prices[] | 各实例比较单价 | number[] | calc | 最高/最低比值 ≤1.2，否则提示换实例【规范】 |
| indicated_unit_price | 比较法比准单价（元/㎡） | number | calc | 综合（算术/加权，口径待核） |
| income_unit_price | 收益法收益单价（商业时） | number | calc | 二期，商业可能需要两种方法 |
| final_unit_price | 最终评估单价 | number | calc/manual | 多方法加权，估价师可干预并留理由 |
| market_total_value | 假定无法定优先受偿权下市场总价（万元） | number | calc | =最终单价×建筑面积（口径一致） |
| priority_claims_total | 法定优先受偿款（万元） | number | manual | 来自 rights.priority_claims |
| mortgage_value | **抵押价值**（万元） | number | calc | =市场总价−法定优先受偿款 |
| mortgage_net_value | 抵押净值（如委托要求） | number | calc/manual | 抵押价值再减预期损失/税费，土增税等复杂项走假设【待核】 |
| amount_in_words | 金额大写 | string | calc | 与阿拉伯数字强制一致 |
| method_selected | 选用方法及理由 | text | calc+manual | 技术报告"估价方法选用" |
| calc_process_doc | 测算过程段落+系数表 | doc block | calc | 插入技术报告，含每步取值依据 |
| qc_flags | 校验结果（勾稽/区间/合规） | object | calc | G1 市场区间 + G2 合规，见 A3 PRD 第 8 节 |

## 4. 待估价师补全/核验清单（落到采集清单 F3/F4）

1. 查勘表/受理单真实字段 → 增删 1.1–1.7 字段，确定必填项与枚举值。
2. 比较法修正系数的**本地经验取值区间**（楼层、朝向、装修、成新、年代、临街、时间）→ 填 `k_*` 的取值规则。
3. 比准综合方式（简单算术 or 加权）、权重口径。
4. 抵押净值是否常规要做、扣哪些项；报告有效期公司口径。
5. 银行是否指定模板/字段、入围要求。
6. 字段命名与公司现有估价宝/WorkBuddy 是否需要对齐导入导出。
