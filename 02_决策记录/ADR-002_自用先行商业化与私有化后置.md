# 决策记录 ADR-002 · 阶段定位澄清：两人自用提效先行，商业化与私有化后置

- 日期：2026-09-16 ｜ 项目：房地产评估 AI 产品 ｜ 状态：Accepted ｜ 补充/微调 ADR-001、BRD v0.1

## 背景（用户 2026-09-16 澄清）

1. **人物合一**：R11 资料中的"吴总（国扬评估技术负责人兼业务总监、资深资产评估+房地产估价师）"= 用户的估价师合伙人 = 用户爱人，持房地产估价、土地估价、资产三证；**去竞品（深圳房讯通灵顾）付费培训的就是他本人，受其任职公司委托前往**。国扬评估即其任职的海口小型评估公司。（关闭 ISSUES-001）
2. **老板当前不付费**：公司老板参训/了解 AI 后**暂时不愿付费**，但确实**可能成为未来付费客户**；当前既不是产品用户，也不是出资/合伙方。
3. **早期使用者是开发+合伙人两人**：开始用的不一定是老板，而是"我和合伙人"；目标是**先让我们自己用好**，暂无对外演示/商业化/融资预期，也没有硬时间点。
4. **部署形态不是重点**：能接受云端；前期公司内网、私有化都可以；原则是"怎么方便、怎么节约架构怎么来"。
5. 确认进度：**Q3（首战场景）已确认=个贷**（见决策 4）；**Q6 仍待用户去问**——第三方成交/案例数据是否愿付费及预算量级、合伙人每周可稳定投入工时与能否持续供料/审报告。另："公司是否有可研业务"这一二义表述待顺手向合伙人澄清（不影响首战）。

## 决策

1. **本期定位为"两人自用的评估提效工具"**，首要成功标准 = 合伙人在**真实项目**里省时间、产出能过三级审核、并愿意持续用（自用版 G2）。对外签约/付费客户验证**后置**，不在近期目标与排期中考核。
2. **架构从简、开发效率与成本优先**：云端、本地脚本、现成 Agent + 可插拔技能均可，哪种省事省成本用哪种；**本期不提前做多租户、私有化安装包、机构权限体系、计费**。"本地/私有化部署、数据不出公司"保留为**将来卖给机构时的能力选项与差异化卖点**（BRD 竞争定位不变），但不构成本期架构约束。
3. **商业关系**：老板当前定性为"潜在客户"，不签协议、不分成、不依赖其资源。仅使用**脱敏**材料做样板；合伙人公司数据/职务成果用于自研产品的授权边界、产品 IP 归属、未来与公司的合作分成，**在对外商业化前再处理**（ISSUES-013），自用阶段不阻塞，但需有意识。
4. **首战场景确认为个贷抵押报告**（比较法为主）。**【Q3 已回复 2026-09-16】合伙人明确：最痛、量最多、时效要求最快（"要求要快"）的就是个贷，尖刀获一线确认，不调整。** 竞品主打的"可研约 3 分钟成稿"，合伙人判断**实际暂时做不到**，且**公司可能没有可研业务**（"没业务"为用户推测、二义待消歧，但两种解读都指向可研非试验场需求）→ 可研（E 线）首期不做、降级观察，不为"炫技"改尖刀。

## 被放弃/推迟的备选

- 一开始就按"卖给机构的私有化产品"做重架构（多租户/权限/安装部署）→ 推迟，两人自用用不上、拖慢验证。
- 现阶段以"说服老板付费/签约"为里程碑 → 推迟，老板明确暂不付费，强推会扭曲产品；先把自用价值做出来，付费是结果不是目标。

## 后果 / 何时重新评估

- 正面：MVP 更轻、更快见到合伙人真实提效；近期指标聚焦"工时下降 + 过审 + 持续使用"，商业指标后置。
- 风险：自用场景与未来机构客户场景可能有差距（如多人协作、权限、数据不出公司），届时以增量方式补，不提前过度建设。
- 重评触发点：① 合伙人自用稳定提效、报告过审（自用 G2 达成）；② 老板或外部机构主动表达付费意向；③ Q3/Q6 回来后场景或资源假设变化。
