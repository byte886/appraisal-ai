## 1. 平台定位（shot_08，事实）

- 一句话：**企业级 AI 智能体平台 = Skill + MCP + 本地知识库 + 智能体编排**。
- 总公式（屏幕底部）：**Skill工厂 + MCP连接 + 知识库 + 智能体编排 = 业务智能体生产线**。
- 设计目标：人只给目标，系统自主执行全流程；不换工具、不改现有业务流程（降低落地阻力）。

## ★ 官方五层架构（横向业务流 × 纵向能力栈，shot_30，A0 底座主骨架）

屏幕副标题原话："**横向是业务流，纵向是能力栈**"。

**横向业务流（闭环）**：立项 → 查勘 → 调研 → 测算 → 报告 → 复核 → 归档 → **知识沉淀**（末环橙色，回流数据层）。对应国标11步并多了"知识沉淀"，即每单作业结束把成果沉淀回知识库（=知识资产化闭环）。

**纵向五能力层（自上而下）**：
| 层 | 组成（屏幕原文） | 说明 / 我方对应 |
|---|---|---|
| **治理层**（贯穿，橙色） | 身份权限·审计日志·审批门控·策略引擎 | 企业级安全合规，横切全部层；对应07安全 |
| **数据与知识层** | 项目库·报告库·案例库·政策库·模板库（五库） | 可研系统的政策/案例/模板库即此层落地实例 |
| **Skill 层** | 资料清单·可比初筛·报告初稿·AI初检·知识问答 | 评估主流程5个核心**原子Skill**（按作业环节切，区别于18Skill按业务线切） |
| **智能体层** | 项目经理·估价师·复核人·风控·知识问答 | **按岗位角色设Agent**（多Agent编排的落地形态=岗位数字员工） |
| **接入层** | 多模型网关·公有云/私有化/本地·统一API | 多模型可切换、三种部署、统一接口 |

- 运行关系【推断】：业务流某环节（如"报告"）→ 智能体层对应角色Agent（估价师Agent）→ 调 Skill层原子能力（报告初稿/可比初筛）→ 读写数据层五库 → 全程受治理层权限/审计/门控约束 → 经接入层多模型网关调模型，归档后知识沉淀回五库。
- 要点：①**接入层明确支持私有化/本地部署**——竞品也能私有化，我方差异化不能只讲"私有化"，要落到更轻、更贴身、本地陪跑；②A0 PRD 以"五能力层+业务流闭环"为主骨架，下文"四件套（Skill工厂/MCP/知识库/编排）"是其实现机制；③Skill层5原子能力与18Skill是"环节视角/业务线视角"两张地图，03已做对照，勿重复建设。

## 2. 四大核心能力（A0 PRD 的一级功能骨架）

### 2.1 Skill 工厂（把专家经验封装成可调用技能）
- 【事实·shot_07/08】输入需求描述，AI 自动生成 Skill，宣传"无需编码"；一人跑通、全员复用；**约 2 周交付一个新 Skill**；shot_04 显示平均产能 **2 个/周**，已有 18 个 Skill 在生产环境每天运行。
- 【事实·shot_07】后台含 **skill-creator**（"创建技能：将现有流程/报告生成经验沉淀，半自动创建技能"）——即"用 Skill 造 Skill"的元工具。
- 【事实·shot_16 反证，重要】复杂报告 Skill 底层并非纯无代码：实际工程含 `.claude`（Claude Code）目录与 Python 代码，按章节工程化搭建、持续迭代约 1 周。→ A0 PRD 要区分两层：**业务人员可见的"半自动 Skill 生成层"** 与 **工程师的"代码工程层"**，不要按"全程零代码"做可行性预期。

### 2.2 MCP 连接（打通业务系统，Agent 直接读写）
- 【事实·shot_08】对接企业 CRM、OA、数据库等内外部工具/数据源；**Agent 直接调用业务系统、读写业务数据，不换工具、不改流程**。
- 【事实·S2】已与**估价宝**打通：审核结果/识别估值数据可回写、自动生成业务工单，无需手动录入。
- 【推断】MCP 是当前主流的"模型-工具"标准协议；我方 A0 可直接采用 MCP 作为对接估价宝/飞书/数据库的统一适配层，避免点对点硬编码。

### 2.3 本地知识库（私有 RAG，主打"告别幻觉"）
- 【事实·shot_07/08】企业文档、报告、案例沉淀为**私有知识库**，做检索增强生成（RAG）；Agent 回答基于真实业务数据，宣传"**告别 AI 幻觉**"。
- 【推断】这是它对冲通用大模型"编造网站/电话"问题的核心卖点，也是评估行业（要可回源、要合规）的刚需。我方报告 MVP 必须把"每个结论可回溯到知识库具体文档/案例"作为硬指标。

### 2.4 智能体编排（多 Agent 协作）
- 【事实·shot_08】多 Agent 协作，复杂任务**自动拆解 → 分配 → 汇总**；人只给目标，系统自主执行全流程。
- 【事实·shot_11】编排层提到 **CCPark + 灵顾多智能体编排**（CCPark 具体所指【待核实】）。
- 【事实·S3/A3】报告即由"市场背景、区位分析、比较法计算、收益法计算、案例筛选、地图截图、排版"等多个 Skill/子 Agent 编排拼装而成（详见 04）。

### 对我方 A3 的工程启示（推断）
1. 报告 Skill = **章节级模块库**，而非一个巨型提示词；公共章节一次沉淀、多份报告复用；
2. 每个章节模块 = 章节 Prompt + 该章知识库检索 + 输出模板，逐章生成、最后拼装、统一排版；
3. "可研报告公共部分"说明它把**跨项目通用章节单独沉淀**（公共部分），项目特有部分另做——我方个贷报告也应区分"公共章节库（区位/市场/政策）+ 项目专属章节（本套房产测算）"；
4. 技术选型现实参考：Claude Code 辅助 + Python 模块化工程，2 人团队完全可复制该模式。
