> 来源：现场人员代拍 13 张（原始逐张提取见 `../training_shots/现场截图情报提取_第3批13张.md`）。
> 价值：这是目前**唯一被端到端拍全的竞品真实产品**（后台IA + Skill机制 + 模板 + 知识库 + AI编程生成过程），既是新业务线 E（可研/投资咨询报告）的证据，也是我方 A3 报告引擎最直接的"参考实现"。除标注外均为【事实·屏幕可见】。

## 1. 这是什么

- 「**可研报告生成管理系统 ©2026**」，本地 `http://localhost:5000`（Python Flask 特征），内网 192.168.0.159；与"估价宝""**分身岛-FXT-AI后台管理系统**"并列打开（FXT 疑=房讯通；分身岛疑为其 Agent 后台品牌，【待核实】）。
- 用途：选择报告类型 → 填一张结构化参数表单 → 系统结合测算表/知识库/公共章节，自动生成一份完整 Word 可研报告。
- 主攻方向【推断】：**双碳/新能源（分布式、集中式光伏）+ 农业农村/乡村振兴（农业、农产品、土地整治）**，按"一县一项目"批量出报告；案例均在湖南县域（益阳赫山、常德安乡、益阳50MW集中式光伏）。

## 3. 六层运行机制（我方报告引擎可直接对照实现）

| 层 | 竞品做法（屏幕原文/可见） | 我方 A3/可研 对应设计 |
|---|---|---|
| ① 模板层 | Word `.docx`，放在生成Skill的 `template` 目录，系统只读、用 Word/WPS 维护；已见 6 类：光伏1809KB、农业1933KB、土地整治12.4MB、工业685KB、管线2532KB、贝贝南瓜11.6MB | 估价师在 Word 里做报告模板+占位符，不依赖开发 |
| ② 生成Skill层 | `feasibility-report`：**上传ZIP→自动读 SKILL.md→解压到 skills 目录→结构检查(可用)→绑定报告类型**；系统不提供默认Skill，引擎与Skill解耦、可插拔 | 每类报告一个可插拔 Skill 包（含模板/逻辑/SKILL说明） |
| ③ 公共章节Skill层 | 7 个可复用章节：位置境域/地形地貌/水文条件/气候条件/地震强度/经济社会发展概况/政策检索；独立启用/上传 | 公共章节库（区位/市场/政策/自然条件）一次沉淀、多报告复用 |
| ④ 报告类型配置层 | 类型=显示名+项目类型+业务类型+**用户输入卡片(config目录)+placeholders.json占位符+生成Skill+勾选公共章节(逗号分隔)**；**配置存本地JSON、暂不入库** | "一类型一配置"，新增品类=换模板+换字段+勾章节，边际成本极低 |
| ⑤ 用户输入层 | `/reports/new` 结构化表单（"输入卡片"），字段随类型变；光伏字段：项目名称*、项目类型、政策分类、类型描述、国家战略主题、项目地区*、城市、地区全称(省市县联动)、年平均总辐射范围、太阳能资源评价、全寿命期衰减率、省份 | 个贷报告对应"房产信息+权利人+贷款信息"等输入卡片，必填校验、地区联动 |
| ⑥ 生成引擎层 | 读测算表.xlsx + `_params.json` → 调公共Skill(政策检索查1万+库) → **python-docx 填充 Word 占位符** → 输出 output.docx；自动校验(可打开/无未替换占位符/已调公共Skill)；一份约 **3m22s** | 同样"取数→章节生成→占位符填充→成稿自检"流水线 |

- 关键解耦思想：**引擎（代码，稳定）与 Skill/模板/配置（业务，常变）分离**；公共章节与项目专属内容分离；模板（Word）与逻辑（Python）分离。这正是它能让非开发人员维护内容、并快速复制到 6 个可研品类的原因。

## 4. AI 编程开发方式实锤（shot17/18/19）

- 用 **OpenAI Codex CLI v0.149.1**，模型 `gpt-5.6-luna medium`（内部/代理模型名【待核实】），输入 `yolo` 开 YOLO 自动执行模式；自然语言下指令（"理解下整个项目""帮我生成一个光伏的可研报告"），Codex 自主跑 PowerShell / python-docx / rg / json 读取。
- Codex 自述架构："**Excel 模板 + JSON 计算卡片 + Python 引擎/填充器**"。
- 与 Claude Code（.claude，shot16）、Cursor（shot06）**三套 AI 编程工具并用**。
- 并不丝滑：出现模型 404（gpt-5.6-luna 找不到，39s 重试）、rg os error 123；生成需 3 分多钟。→ 我方预期：AI 编程提效显著但需容错重试，不是一次成型。

## 5. 知识库（RAG）构成

- **政策法规库 10776 条**：批量导入（一次 10716 条）、带审核"通过"流；颗粒度到县级/民族自治县地方条例（恭城、琼中、阿坝等）；"政策检索"公共 Skill 即检索此库。
- **项目案例库**：当前仅 1 个（益阳50MW集中式光伏）。
- **银行信息库**：当前仅 1 条（中国农业发展银行，政策性银行，服务融资方案章节）。
- 【推断】政策库是它"告别幻觉、结论可回源"的底气；案例/银行尚空，说明产品在早期快速扩张期。

## 6. 成熟度判断（诚实，我方追赶窗口）

- 【事实】案例库1个、银行库1条、配置存本地JSON不入库、现场仍在边演示边改、有模型404/命令报错。
- 【推断】这是一套**用 AI 快速搭出的内部生产工具，而非成熟商业 SaaS**：架构思路成熟可借鉴，但内容厚度、多租户/协同、稳定性仍早期。我方 2 人团队在"单一品类（个贷）做深做稳"上完全有机会追平甚至反超，不必被"平台感"震慑。

## 7. 给我方的落地清单（A3 MVP 直接照此设计）

1. 技术骨架：Python（Flask/FastAPI 后台）+ python-docx 填充 Word + 本地 JSON 配置起步（后续再上数据库）+ 章节级 RAG 知识库；
2. 让估价师用 Word 维护"个贷报告模板"，在模板里埋占位符（对应 placeholders.json）；
3. 把个贷报告拆成"公共章节（区位/市场/政策/楼盘）+ 专属章节（本套房产比较法测算）"，公共章节沉淀复用；
4. 做"报告类型配置"：输入字段表单可配置、章节可勾选——为后续扩车辆/收益法/可研留好派生口；
5. 成稿自检门：文件可打开、无残留占位符、必备章节都已生成、数值勾稽（单价×面积=总价）；
6. 开发方式：1 名开发用 Claude Code/Codex 搭骨架，估价师作为破壁者持续喂规则与模板，复刻其"10/90"分工；
7. 可研线 E 暂列 P2 观察，但**引擎从第一天就按"多报告类型可插拔"设计**，避免个贷跑通后重构。
